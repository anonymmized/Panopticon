# Правила работы над Panopticon

[Английский](AGENTS.md) | [Русский](AGENTS.ru.md)

Единственное приложение находится в `Sources/Panopticon`. Режим языка Swift 5,
macOS 13+, AppKit для панели и SwiftUI для настроек и поповеров. Без внешних библиотек
и телеметрии. См. [архитектуру](docs/ARCHITECTURE.ru.md).

## Ветки и общие файлы

- Начинай задачи от актуальной `main` в отдельных ветках.
- До параллельных правок согласуй изменения Model.swift, main.swift и формата настроек.
  Используй конкретный контракт границ модели и сервисов.
- Не выполняй push, удалённый PR, публикацию или удалённое слияние без указания владельца.
- Не коммить сборки, кеши, установщики и ключи подписи.

## Проверки

```sh
python3 scripts/check_localizations.py
python3 scripts/check_documentation.py
swift build -c release
.build/release/Panopticon --self-test
.build/release/Panopticon --panel-self-test
./build.sh
codesign --verify --deep --strict build/Panopticon.app
git diff --check
```

Тестам панели нужен macOS WindowServer. В Linux не запускай AppKit-тесты. Реальные
доступы к папкам, музыке и календарям проверяются отдельно по действию пользователя.
Локальный образ создаётся через `./scripts/make_dmg.sh`; это не разрешает публикацию.

## Инварианты

- Состоянием владеет `BarModel`. Связанные поля меняй внутри `batch`.
- `BarSpace` хранит приложения, ярлыки и коллекции; профили — оформление и снимок панели.
  Подключения календарей общие для пространств.
- До переключения сохраняй прежний снимок. После удаления и перестановки выбранный ID
  должен оставаться валидным.
- Новые Codable-поля читай с дефолтом либо делай optional. Нормализуй новые настройки,
  сохраняй существующие данные и стабильную идентичность приложения.
- Панель не получает фокус клавиатуры. Прозрачные поля пропускают клики через
  `ignoresMouseEvents`, включая смену края и увеличение иконок.
- Нативные контекстные NSMenu создавай при клике.
- Системный Dock меняй только при включённой пользователем замене. Сохраняй и возвращай
  точные исходные значения, не удаляй копию при ошибке восстановления.
- Не запрашивай разрешения при старте и фоновом опросе.
- Освобождай таймеры и наблюдателей, используй weak для владельцев замыканий.
- Тесты используют отдельные настройки и созданные файлы. Не очищай настоящую Корзину,
  не меняй пользовательские документы и не подключай реальные разрешения автоматически.
- Документация парная: английская и русская. В английском Markdown нет кириллицы.
  Описывай текущий продукт, историю реализации сохраняй в Git.
