# Архитектура и контракты сервисов

[Английский](ARCHITECTURE.md) | [Русский](ARCHITECTURE.ru.md)

## Владение состоянием

`BarModel` — источник состояния панели. Связанные изменения выполняются внутри `batch`,
чтобы наблюдатели получили одно согласованное обновление. `BarSpace` хранит пути приложений,
ярлыки, коллекции и необязательную привязку к рабочему столу. Перед переключением сохраняется
текущий снимок. После удаления и перестановки выбранный ID должен оставаться валидным.

Профиль хранит оформление и снимок текущей панели. Подключения календарей общие и не
перезаписываются профилем. Новые поля Codable необязательны либо читаются с дефолтом.
Числа и перечисления нормализует `SettingsRules`; отсутствие файла или диска не должно
стирать сохранённый ярлык приложения.

Настройки хранятся в стабильном локальном домене UserDefaults. Состоянием интерфейса
владеет `UIStateStore`. Сессия и копия настроек системного Dock отделены от экспортируемых
профилей. Импорт ограничивается и проверяется, экспорт содержит выбранный профиль,
а не данные восстановления и блокировки сессии.

Текущая реализация не заявляет атомарное версионируемое файловое хранилище. Его внедрение
требует отдельного контракта миграции и тестов обратного чтения до замены существующего
способа хранения.

## Выполнение и окна

`AppDelegate` координирует сервисы, меню и поповеры. `DockWindowController` владеет
неактивирующей AppKit-панелью. `PanelPlacement` определяет монитор и геометрию,
`PanelContentLayout` согласует размеры для рисования, кликов и доступности.
Прозрачные поля пропускают клики на уровне окна.

`DockVisibilityPolicy` — независимый автомат состояния. Автоскрытие начинает работу
со скрытой панелью, использует задержку наведения и ухода, не считает активацию и обычный
клик поводом для показа. Поповер удерживает только уже видимую панель. Переходы обзора
и пробуждения не должны оставлять устаревшее разрешение на показ.

Системный Dock меняется только после включения замены. Перед записью сохраняются три
настройки видимости. Копия проверяется, остаётся после ошибки восстановления и применяется
при обычном выходе. Списки закреплённых приложений только читаются. Mission Control
остаётся системным; наша панель уступает ему, чтобы избежать наложения.

## Границы сервисов

| Компонент | Ответственность |
|---|---|
| `AppCatalog` | Локальный поиск приложений и ранжирование |
| `CalendarController` | Чтение разрешённых событий и защита от устаревших ответов |
| `MusicController` | Источник плеера, явный доступ Automation и данные воспроизведения |
| `FocusTimer` | Сохранённая фокус-сессия и следующая длительность |
| `FolderPresentationLoader` | Фоновое ограниченное чтение папки и отмена устаревшего результата |
| `BadgePoller` | Необязательные чтения Accessibility вне главного потока |
| `SessionLifecycle` | Единственный владелец, kernel lock и согласованное восстановление |
| `PanelActions` | Проверенные команды интерфейса и отмена изменений набора |
| `Localization` | Каталоги, подстановки, формы чисел и смена языка |

Публикация состояния интерфейса выполняется в главном потоке. Фоновый запрос сохраняет
поколение и отбрасывает устаревший результат. Новые асинхронные сервисы должны иметь
отмену, слабые ссылки владельцев и освобождение таймеров и наблюдателей.

Разрешения запрашиваются только по действию пользователя. Старт и фоновый опрос их не
запрашивают. Нативные контекстные меню создаются при клике. Операции с реальными файлами
явные и отделены от удаления ярлыков.

## Исходники

Swift-код находится в `Sources/Panopticon`. Визуальные токены реализованы в
`DesignSystem.swift`, `Theme.swift` и `PanelPalette.swift`; справочник —
`design/design_tokens.json`. Переводы упаковываются из `Sources/Panopticon/Resources`,
метаданные сборки берутся из `resources/Info.plist`.

История разработки и исходные предложения сохранены в Git. Этот документ описывает
работающие интерфейсы и не выдаёт спроектированные API за реализованные.
