# Проверки производительности Codex

Дата: 2026-10-14. Контрольный Mac: Apple M5 Pro, arm64, macOS 26.6.2 (25G83),
встроенный Retina 1512×982 pt / 3024×1964 px, scale 2. Системный Reduce Motion
включён. Результаты относятся к этой машине и текущей разработческой ветке.

## Сравнение одинакового AppKit-сценария

`PresentationBenchmark.swift` компилируется без изменений и против исходного
commit `53dd4a3`, и против текущей версии. Изолированная UserDefaults suite;
4 установленных приложения, 2 виджета (часы/календарь), 4 края; внешние
интеграции/бейджи выключены. На край — 300 refresh, первые 20 исключены;
1120 измерений layout и 112 offscreen bitmap drawing после прогрева.
Отрисовка не обращается к пользовательским папкам/календарям/плеерам.

```sh
./scripts/compare_baseline.sh 53dd4a3
build/NewMacBar.app/Contents/MacOS/NewMacBar --ui-benchmark > build/current-benchmark.json
```

| Показатель | База 0.5 | Новая реализация |
|---|---:|---:|
| Layout median, ms | 0.0343 | 0.0303 |
| Layout p95, ms | 0.0426 | 0.0416 |
| Bitmap draw median, ms | 2.189 | 2.122 |
| Bitmap draw p95, ms | 2.474 | 2.530 |
| Maximum resident set, bytes | 51 265 536 | 52 674 560 |

Это одиночные локальные прогоны. Время сравнимо; разницу нескольких процентов
нельзя интерпретировать как устойчивое ускорение. RSS вырос примерно на 1.34 MiB.
RSS в этой таблице не подменяет physical footprint.

Первый вариант overflow делал рекурсивные вычисления на каждом обращении к
иконке: layout median был 2.53 ms. Эта регрессия найдена сравнением и устранена:
`PanelContentLayout` теперь вычисляется один раз при refresh/resize и используется
для drawing, hit testing и AX. Изображения коллекций не перечитываются на каждом
refresh, кеш иконок ограничен текущим отображаемым набором. Задержки AX вынесены
из main thread в BadgePoller.

## Покой реального приложения

`run_platform_probe.sh` создаёт подписанную ad-hoc копию с отдельным bundle ID
и одноразовым доменом настроек. Исходный домен NewMacBar не меняется. Видимая
панель слева, 4 приложения, настройки закрыты; все виджеты, внешние интеграции,
showRunning, autoHide и followMouse выключены. Замена системного Dock выключена.

```sh
./scripts/run_platform_probe.sh 300 build/idle-probe.json
```

После 15 секунд прогрева две выборки `getrusage` и `TASK_VM_INFO` берутся вокруг
пятиминутного интервала. CPU = процессорное время / wall time × 100; 100% — одно
логическое ядро. Во время интервала нет периодических записей измерений на диск;
JSON записывается один раз в конце, затем тестовый экземпляр выходит и его
временный домен удаляется. Physical footprint берётся у самого процесса через
Mach, а не вычисляется из RSS. Финальная процедура с неизменной обёрткой завершилась с exit 0:

| Показатель | Результат |
|---|---:|
| Измеренный wall time | 300.998 s |
| Процессорное время | 0.085169 s |
| Среднее CPU, одно ядро = 100% | 0.0283% |
| Physical footprint в конце | 13 878 088 bytes |
| Maximum resident set | 73 039 872 bytes |

Питание — Battery Power (в ходе проверки было 75%). На протяжении этого
изолированного сценария цель idle ≤0.5% и footprint ≤150 МБ выполняется.
Это один сценарий на одном Mac; он не подтверждает энергетические свойства
плеера, календаря, Low Power Mode и всех вариантов экранов.

После добавления kernel flock отдельно прошёл live smoke: CLI получил
подтверждение восстановления от владельца, второй процесс активировал первый,
обычный выход очистил marker. Измерения smoke с открытыми настройками в idle
таблицу не включаются. Дополнения меню «Правка» и системного seed Safari после
этого прогона не добавляют фоновых таймеров; после C03–C07 процедуру повторить.

## Практические ограничения приёмки

Полного Xcode/Instruments в используемом toolchain нет: `xcrun xctrace` недоступен.
Time Profiler/Allocations/Energy, 100 циклов открытия всех поверхностей и длинный
seamless сценарий на целевых машинах требуют отдельного прохода после C03–C07.
Не пройдены 72 часа/7 дней беты, Intel, внешний дисплей с другим масштабом,
120 Hz и физические sleep/lock/unplug сценарии. Отсутствие ошибок короткого
AppKit-прогона не доказывает отсутствие утечек или выполнение frame-time SLA.

Существующие чтение/индексация приложений, хранение настроек, SiteIconCache,
плеер и календарь остаются сервисами Claude. Их итоговые I/O, отмена, кеши и
частота обновления проверяются повторно после интеграции. В этой ветке не
объявлено прохождение всей таблицы метрик master plan.

Первый запуск пробы обнаружил существующий crash с `widget=none` и
`secondaryWidget=none`: didSet повторно присваивал `none` без условия выхода.
Он исправлен одной строкой в Model.swift и отдельной регрессией сохранения/загрузки.
Неуспешная проба в результаты CPU/footprint не включается.
